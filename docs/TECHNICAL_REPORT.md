# 技术报告（Technical Report）

> 项目：基于大五人格与AI态度量表的网页心理测评系统
> Agentic AI Web Assessment Challenge 课程提交
> 数据来源：系统后台 11 名试点用户真实作答（截至 2026-09-13），均为匿名数据

---

## 1. 我构建了什么系统？

我构建了一个面向课程科研的**网页心理测评系统**，全栈 Node.js 驱动，无数据库，作答数据以 JSON 持久化于火山引擎 TOS 对象存储。系统包含四个页面：

1. **知情同意页**：说明测评目的、数据用途与隐私措施，勾选同意后方可进入问卷；
2. **问卷填写页**：依次呈现大五人格量表（25题）与 AI 态度量表（15题），共40题，5点李克特单选，含必填校验与进度提示；
3. **受试者结果页**：雷达图展示大五五维度得分，呈现 AI 态度三子维度得分与中性文字解读，并明确标注"不构成临床或医学诊断"；
4. **管理员后台**（口令鉴权）：样本统计、单题分布、Cronbach's α、大五×AI 相关矩阵、原始作答明细查看与单条删除。

整体风格学术简约（白底灰字、圆角卡片），避免商业测评网站的夸张引导。

## 2. 我测量了哪些心理构念？

系统测量两大构念群，各构念定义与题项来源如下。

**2.1 大五人格（Big Five / FFM）**——共25题，每维度5题：

| 维度 | 定义 |
| --- | --- |
| 外倾性（Extraversion） | 个体在社交情境中的活跃、健谈、主动参与程度，以及从人际互动中获得能量的倾向 |
| 宜人性（Agreeableness） | 同理心、合作性、对他人的信任与包容程度 |
| 尽责性（Conscientiousness） | 条理性、计划性、自律性与对任务目标的责任意识 |
| 神经质（Neuroticism） | 体验焦虑、担忧、情绪波动的倾向；低分代表情绪稳定 |
| 开放性（Openness） | 对新观念、抽象思考、审美体验与新经验的好奇与接纳程度 |

**2.2 人工智能态度**——共15题，三个子维度各5题，另派生1个总分：

| 子维度 | 定义 |
| --- | --- |
| AI收益感知 | 对 AI 在学习效率提升、复杂任务辅助、创意启发等方面实际价值的评价 |
| AI风险感知 | 对 AI 内容错误、隐私泄露、过度依赖削弱独立思考、安全隐患等风险的关注程度（独立构念：高分=风险意识强，不等同于否定 AI） |
| AI使用意愿 | 在学习场景中主动使用、持续学习并尝试新 AI 产品的行为倾向 |
| AI总态度（派生） | 全部15题的综合均分，反映对 AI 的总体态度倾向 |

**题项来源与许可（reuse basis）**：大五人格维度定义依据 McCrae & Costa 的五因素模型及 John & Srivastava (1999) 的经典维度界定，但**具体题项为开发者自编的中文简短表述**，并非 NEO-PI-R、BFI/BFI-2 等授权量表的翻译或改编；AI 态度题项同样为开发者自编，构念思路参考 Davis (1989) 技术接受模型（TAM）的感知有用性/使用意愿结构及 AI 态度研究中的风险感知取向。五因素结构属公共学术知识，自编题项仅用于本课程教育用途，不作商业发行。

## 3. 为什么选择这些构念？

- **选择大五人格**：五因素模型是人格心理学中实证支持最充分、跨文化复现性最好的特质结构，适合作为测量稳定人格倾向的标准框架，且五维度结构简洁，便于在有限题量（25题）内完成可靠测量。
- **选择 AI 态度**：AI 工具已深度嵌入大学生及应届毕业生的学习与求职过程，但"人格特质如何影响个体接受 AI"这一问题仍缺乏本土化实证资料；将稳定的人格特质与新兴技术态度结合，可探讨人格因素对技术接受度的预测作用，具有现实针对性。
- **将风险感知独立成子维度**：预实验设计时即注意到"认可 AI 价值"与"警惕 AI 风险"并非同一连续体的两端，因此未把风险题反向计入总分了事，而是独立计分，避免概念混淆。

## 4. 计分系统如何工作？

**4.1 反应量表**：全部40题采用5点李克特量表（1=非常不同意，2=不同意，3=中立，4=同意，5=非常同意）。

**4.2 题目—子量表映射**：
- 大五：E1–E5（外倾）、A1–A5（宜人）、C1–C5（尽责）、N1–N5（神经质）、O1–O5（开放），各5题；
- AI：BEN1–BEN5（收益）、RISK1–RISK5（风险）、USE1–USE5（意愿），各5题。

**4.3 反向计分规则**：共16道反向表述题，题号为 3、5、7、9、12、14、17、19、22、24、27、29、32、34、37、39（开放性组反向题位于第3、5位，其余维度组位于第2、4位）。反向题先按 `转换分 = 6 − 原始分` 换算，使维度内所有题项方向一致。

**4.4 合成公式**：
- 维度分 = 该维度5道题（同向化后）算术平均分；
- AI总态度分 = 15道 AI 题（同向化后）算术平均分。

**4.5 分数范围与解读边界**：各维度得分区间 1.00–5.00；结果页三等分解读：<2.33 偏低，2.33–3.66 中等，≥3.67 偏高。所有解读为中性描述并附非诊断声明，不提供任何临床判定。

**4.6 缺失值策略**：前端强制40题全部作答（未答完不可提交）；服务端 `isValidAnswers` 校验题数（必须为40）与取值范围（1–5整数），不合规请求直接拒绝，因此入库记录无缺失值；旧版题数不一致的历史记录在统计时跳过（保留文件但不纳入计算）。

**4.7 用于验证计分实现的测试**：
1. 边界用例：全选1、全选5、交替选择，提交后与手算维度分逐项比对；
2. 反向题专项：用全选"非常同意"用例验证含反向题的维度是否达到理论极值，曾据此发现初版漏算反向题的 bug；
3. 统计函数：Cronbach's α 与 Pearson r 用已知小型数据集交叉验证；n=1 零方差时显示"—"而非 NaN。

## 5. 我使用了哪些技术？

- **前端**：HTML5 + TailwindCSS（CDN）+ 原生 JavaScript（ES6）；雷达图与统计图使用 Chart.js 4（CDN）；无前端框架。
- **后端**：Node.js（≥18）+ Express 4，提供题库下发、作答提交、结果查询、管理统计、记录删除、存储诊断等 REST API。
- **存储**：火山引擎 TOS 对象存储（`@volcengine/tos-sdk` 2.9.1），数据为单个 JSON 对象；未配置 TOS 时回退本地文件（原子写入）。写前自动快照到 TOS `backups/` 前缀。
- **部署**：后端为腾讯云 SCF Web 函数（Node.js 18.15，1024MB，超时60秒），经 HTTP 触发器提供 API；前端静态页托管于 GitHub Pages；CORS 在 SCF 触发器侧配置。
- **运维脚本**：Node 脚本完成 ZIP 打包、函数代码更新、CORS 配置，密钥全部走环境变量。

## 6. 我如何使用 Agentic AI？

以 Trae IDE 内置智能体为核心，AI 贯穿需求拆解、代码生成与调试部署全流程：承担前端页面、Express 路由、统计函数、部署脚本等模板化代码的编写；协助定位计分、跨域、无状态丢数据、TOS SDK 字段错误等问题。核心业务规则（题面方向、计分规则、架构选型、数据安全策略）由本人决定并逐项审查。完整的关键交互记录见 [AI_DEVELOPMENT_RECORD.md](./AI_DEVELOPMENT_RECORD.md)，试点数据见 [PILOT_EVALUATION.md](./PILOT_EVALUATION.md)。

## 7. 我从试点中学到了什么？

试点 N=11，均为22岁左右本科刚毕业生（校园→职场过渡期、AI 使用经验丰富）。

**描述统计**：

| 维度 | 均值 | SD | 维度 | 均值 | SD |
| --- | --- | --- | --- | --- | --- |
| 尽责性 | 3.84 | 0.65 | AI使用意愿 | 4.44 | 0.54 |
| 宜人性 | 3.65 | 0.31 | AI收益感知 | 4.05 | 0.48 |
| 开放性 | 3.60 | 0.31 | AI风险感知 | 4.04 | 0.28 |
| 外倾性 | 2.93 | 0.60 | AI总态度 | 4.18 | 0.38 |
| 神经质 | 2.62 | 0.71 | | | |

- 高尽责、低神经质符合该群体在求职学业压力下的目标导向特征；AI使用意愿最高，呈数字原住民的工具使用惯性。
- 风险感知与收益感知几乎持平（4.04 vs 4.05），打破"高收益感知必然伴随低风险意识"的假设，提示该群体对 AI 保持理性警觉。

**信度（Cronbach's α）**：神经质 0.852、AI使用意愿 0.771、AI总量表 0.758、尽责性 0.738 可接受或良好；外倾性 0.656 接近下限；AI收益感知 0.420、开放性 0.280、宜人性 0.035 偏低；AI风险感知为 **−0.620**。结合单题分布，风险题反向换算后均值均在3.82–4.27，呈严重天花板效应，加之小样本、群体高同质，导致题间相关不稳定。

**相关分析**：尽责性×AI风险感知 r=0.667（p=0.025），神经质×AI收益感知 r=−0.638（p=0.035），其余不显著（受样本量限制）。

**结论**：量表基本可用，但风险感知维度区分度不足、部分维度受天花板效应拖累信度，正式施测需修订题目并扩大、多样化样本。

## 8. 我遇到了哪些工程问题？

1. **C盘空间不足**：node_modules 与部署 ZIP 体积较大，需频繁清理临时文件与旧包。
2. **SCF 无状态丢数据**：容器实例回收后本地磁盘数据全失，初期"看似保存实则消失"；改用 TOS 持久化解决。
3. **CORS 跨域**：GitHub Pages 与 SCF 不同源，浏览器拦截 API；在 SCF 触发器配置跨域规则解决。
4. **Content-Disposition 强制下载**：SCF 默认域名对 HTML 强制加 `attachment` 头，浏览器下载而非渲染；前端迁至 GitHub Pages、后端仅出 API 后解决。
5. **TOS SDK 字段差异**：tos-sdk 2.9.1 的 `getObject` 内容位于 `res.data`（Buffer）而非 `res.content`，读取已存在数据时静默回退空数组，导致每次提交覆盖历史；通过管理诊断端点暴露错误后定位并修复。

## 9. AI Agent 犯了哪些错误？

1. **计分逻辑错误**：初版遗漏部分反向题换算，含反向题维度得分系统性偏低；开放性反向题位置识别错误（第3、5位 vs 其余组第2、4位）。
2. **持久化逻辑错误（最严重）**：取错 SDK 响应字段且失败时静默返回 `[]`，叠加内存缓存掩盖了持久化失效，导致历史数据被反复覆盖。
3. **测试脚本误清线上数据**：`test-tos.cjs` 直接使用线上对象 key 并在末尾清空数据，运行即清空真实记录。
4. **跨域遗漏**：初版未在 SCF 触发器配置 CORS，前后端分离后接口全部被浏览器拦截。
5. **打包路径问题**：打包脚本未排除 data/ 与 scripts/，部署包膨胀且夹带无关文件。
6. **统计口径错误**：独立核对脚本误读测试夹具而非落盘数据，产生虚假的记录数告警。

## 10. 我如何验证并修正这些错误？

建立四层验证机制：

1. **人工逻辑校验**：逐题核对题面方向，`lib/questions.js` 中以 `reverse` 标志作为计分唯一数据源，计分函数统一读取。
2. **本地单元级验证**：全选1/全选5/交替选择用例手算比对；经典小数据集交叉验证 α 与相关系数。
3. **端到端验证**：真实提交→直读 TOS 核对落盘→核对后台统计→删除测试数据，跑通完整链路（验证了连续两次提交"追加而非覆盖"）。
4. **诊断端点**：新增 `/api/admin/diag-storage` 结构化返回底层错误，绕开 SCF 日志不可查的问题。

配套加固：测试脚本隔离到 `responses-test.json` 专用 key；TOS 读取失败改为抛错而非静默空数组；每次写入前自动快照；打包脚本补排除规则。

## 11. 如果再多一周，我会如何改进？

1. **量表修订**：重写 AI 风险感知题目（如增加"我使用 AI 时会主动核实输出"类高区分度题），重估宜人性、开放性题项，目标各维度 α>0.70；
2. **数据导出**：后台增加 CSV 导出；TOS 快照改为按版本号策略，避免对象膨胀；
3. **统计增强**：回归分析、分组比较、结果页加入样本均值参照；
4. **权限模型升级（首要）**：当前系统采用单一全局口令，任何持口令者进入后台均可查看全部被试的原始作答数据。规范的心理测评系统应支持多管理员分群体隔离：每位施测者持有独立口令，口令（或携带标识的问卷链接）与测试群体绑定，后台鉴权后仅呈现该群体自己的作答记录，落实数据最小可见原则，适配多班级、多施测点协作场景；
5. **安全与性能**：API 速率限制、管理员登录态、SCF 冷启动优化；
6. **体验优化**：分页作答、进度百分比、中途保存、记录作答时长（用于质量分析）、匿名结果分享；
7. **扩大试点**：样本扩至50人以上并引入非应届毕业生群体，降低同质性，提升信度估计与相关分析效力。
